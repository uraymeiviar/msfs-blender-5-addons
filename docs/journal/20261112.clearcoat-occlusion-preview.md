## Session 1: Clearcoat and Occlusion Strength in Material Preview and Rendered Views

- **Date:** 20261112
- **Developer:** uraymeiviar, Claude Opus 5.5

### Objective

The maintainer asked whether the viewport previews an MSFS Clearcoat material. It does not. Asobo's tree sends
the clearcoat texture to Coat Tint, Blender 4.2's new name of the socket that was "Clearcoat" before, and leaves Coat
Weight at 0, so no coat shows. Its clearcoat normal goes to Coat Normal without a Normal Map node, and none of the
seven clearcoat parameters reaches a node (Asobo's `TODO` on both setters). Of the general parameters, Occlusion
Strength, Wear, the emissive day and night multipliers and the render and rain options have no preview either.

### Decisions (maintainer)

1. **Preview in the FSS fork, without waiting for Asobo.**
2. **Clearcoat and Occlusion Strength first;** Wear later.
3. **The clearcoat texture layout is left to the agent** (best effort), since nobody at FSS has used the material yet.
   The agent chose the MSFS 2024 SDK's layout, see the design.

### Design

- Code in an FSS-owned module, `io_scene_gltf2_msfs_fss/material_preview.py`, called from lines marked `# FSS` in
  Asobo's files: a mixin on `MSFS2024_Clearcoat`, one call at the end of each clearcoat texture setter and of
  `MSFS2024_Material._update_ao_links`, `update=` on the seven clearcoat properties and on Occlusion Strength, and
  the "Update Material Nodes" button on the Clearcoat panel.
- **Clearcoat:** as in the anisotropic preview, the material's Principled BSDF and its ALL output stay as Asobo builds
  them. A copy of that Principled BSDF (its values and incoming links, coat sockets aside) with the coat layer feeds
  two outputs with targets EEVEE and CYCLES; nodes are named `FSS Coat ...` and are rebuilt on every change.
  - Texture layout: RGB tints the coat (white is clear), A is the coat roughness; Coat Weight 1 on the whole material.
    The SDK documents "Clearcoat Colour (RGB), ClearCoat Roughness (A)" and Asobo's texture library groups the slot
    with the colour textures (base colour, emissive, detail colour). Asobo's label "Clearcoat amount (R), Clearcoat
    rough (G)" is the MSFS 2020 layout; the panel label now reads "Clearcoat Color (RGB), Clearcoat Roughness (A)".
  - Coat roughness = texture A x Clearcoat Roughness Factor (1 without a texture). With Use Uniform Roughness the
    coat roughness is the OMR texture's green channel, the clearcoat texture is not used, and the base layer gets the
    flat Base Roughness.
  - Coat normal: the Clearcoat Normal texture through a Normal Map node of strength Clearcoat Normal Factor. With
    Base Normal Affect Coat: base normal + coat normal - surface normal, normalized (an approximation).
  - Tilings scale the material's UV (after its UV offset, tiling and rotation) for each clearcoat texture.
  - Preview nodes read a copy of the artist's image (`.fss_coat_preview.<colour space>`, alpha Channel Packed):
    Asobo's slot validation keeps the artist's image Non-Color, which would read the tint wrong.
- **Occlusion Strength:** glTF's rule, occlusion = 1 + strength x (texture - 1), clamped to 0..1, as a Math node
  (`FSS Occlusion Strength`) between the OMR group's occlusion and Asobo's Apply AO group. In the ALL tree, so both
  engines show it. Not on Windshield materials, where the property is the Reflection Mask Strength.

### Findings

- **File > Export writes Asobo's coat links as `KHR_materials_clearcoat`** (factor 0, so no visible coat, plus the
  two clearcoat images). A first version that removed those links from the material's Principled changed this export
  (2 fewer images and textures); the links stay, so the export is unchanged. Dropping that useless extension is a
  separate proposal. The multi-exporter and the MSFS 2020 export do not write it.
- Asobo's `force_update_nodes` never calls the clearcoat texture setters, so after a file is opened its coat links
  are gone until the artist sets a texture again. The mixin's rebuild therefore only calls `sync`, not the setters,
  so a reopened file exports as before.

### Verification

- `tests/test_material_preview.py`, 82 checks, all pass: the coat branch and its outputs, each clearcoat parameter
  reaching its node, Use Uniform Roughness, the coat normal in its four cases, alpha modes and normal changes, the
  artist's image unchanged, the Occlusion Strength node (and none on Windshield), a file saved without the preview,
  the update operator.
- Render, plane under a white sky at a grazing view: a smooth coat over a dark base lifts red from 0.302 to 0.557
  (EEVEE) and 0.322 to 0.565 (Cycles); a red tint over a white base gives (0.91, 0.18, 0.18) in EEVEE and
  (0.91, 0.21, 0.21) in Cycles, against 0.91 grey for a white tint.
- Exports against the tree as the add-on built it before (preview nodes and the occlusion node removed, Asobo's coat
  links kept): identical glTF sections and file hashes for the MSFS 2024 multi-exporter, MSFS 2020 and File > Export.
  This is a simulated "before" tree in the same session, not an export by the previous add-on version.
- Suites re-run and passing: `test_anisotropic_preview` (107 checks), `test_materials` (10), `test_normal_scale` (6),
  `test_texture_sets` (6), `test_material_animation` (0 failures).
- E2 cockpit (`COCKPIT.blend`, opened without saving): 48 MSFS materials, no errors; 12 get the Occlusion Strength
  node (all at strength 1, so no visible change), its one Clearcoat material gets the coat branch.
- Not verified: how close the coat looks to MSFS; whether the RGB/A layout matches the simulator (needs a texture
  tried in MSFS).
