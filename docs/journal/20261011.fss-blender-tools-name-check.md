### Problem Statement

The Blender object name becomes the glTF node name, and the model XML, `.cfg` files and attachments find nodes by that exact name. Blender appends `.001`, `.002` when a name is taken, so a copied `LIGHT_NAV_L` exports as `LIGHT_NAV_L.001` and every reference to it misses silently. Names that break the project's naming habit (mixed case, Blender defaults such as `Cube.018`) hide the same kind of defect and make the scene hard to read.

This is the first fss-blender-tools feature (wish-list item 2). The maintainer scoped the first slice: no dependency on the MSFS project, a panel that proposes renames for suffixed names with a batch-rename button, plus checks for improper case and default names, covering objects and bones. The project cross-check comes later through the project-tree query API.

### Findings on the Production Cockpit

Read-only scan of `assets/visual/cockpit/Cockpit.blend` in the portable Blender 5.2:

| Fact | Count |
| :--- | ---: |
| Objects (2558 mesh, 1020 empty, 9 armature, 4 camera) | 3591 |
| Objects with a `.NNN` suffix | 1437 |
| ... of which the name without the suffix is also taken | 814 |
| Object names all upper case / all lower case / mixed (suffix ignored) | 2503 / 227 / 861 |
| Objects with a Blender default name (`Cube`, `Cylinder.042`, `Armature`, ...) | at least 60 |
| Bones (in 9 armatures), none suffixed; upper / mixed / lower | 42; 31 / 10 / 1 |
| Actions, of which suffixed | 87, 13 |
| NLA tracks, of which suffixed | 513, 0 |

Consequences for the design:

- **Most suffixed names cannot simply lose their suffix.** 814 of 1437 collide with an existing base name, mostly repeated parts (`B_GS_AFCS_SPEEDM_SELECT_KNOB.001` to `.008`, `1screwcockpit.001` onward). Blender cannot hold two objects with the same name, and without the project the tool cannot know which copy the XML means.
- **The house style is upper snake case** (`B_GS_AFCS_AT_BUTTON`, 70 percent of objects, 501 of 513 NLA track names). Most mixed-case names are a `_Piece` suffix (`AUDIO_L_AUD_ADF2_LIGHT_Piece`) and most lower-case ones are repeated hardware (`1screwcockpit`).
- **A case change can break a working reference.** MSFS matches names exactly (the real aircraft has a `GPU_line` against `GPU_LINE` defect, validator journal Session 7). Without the project, the tool cannot tell whether `AUDIO_L_AUD_ADF2_LIGHT_Piece` is referenced in that exact spelling.
- **The Asobo LOD naming must survive renames.** The multi-exporter treats names matching `^x[0-9]_` or `_lod[0-9]+$` (case-insensitive) as LODs (`io_scene_gltf2_msfs_fss/io/exp/lod_groups.py`). A suffix breaks the second form (`PANEL_LOD0.001` is no longer a LOD), so stripping it repairs LOD detection; the case check must leave the lower-case `x0_` prefix alone.

### Maintainer Decisions

- **Location:** a new add-on folder `fss_blender_tools/` in the `msfs-blender-5-addons` repository, replacing wish-list decision 1 ("own repository").
- **D1, collisions:** report only. The suffix of a collision is never changed by the tool; which copy the project means is the artist's call. Other fixes (case, characters) still apply to such a name and keep its suffix.
- **D2, case fixes:** proposed in upper case and selected by default, accepting that a case change can break a reference the project uses today until the project cross-check exists.
- **D3, default names:** report only; the row selects the object and the artist types a name inline.
- **D4, object scope:** every object in the file, plus the bones of every armature.
- **D5, later kinds:** actions (13 suffixed; their names reach glTF only when not on a named NLA track) and materials (a `systems.cfg` `EmMeshMaterialName` refers to a material by name) are left for a later slice.

### Solution Intent & Approach

The add-on `fss_blender_tools` (module `name_check.py`) adds the panel *Name Check* to the 3D View sidebar tab *FSS Tools*. It does not use the Asobo code or `_addons_common`, so upstream merges into the exporter stay conflict-free.

- **Scan** fills a list stored on the scene (a `CollectionProperty` of names, not object pointers that could dangle). Objects form one namespace and the bones of each armature another. One row per item with every rule it breaks, one proposed name and a tick box:

| Tag | Rule | Proposal | Ticked by default |
| :--- | :--- | :--- | :--- |
| SFX | `NAME.NNN` and `NAME` is free; when several copies compete, the lowest number wins | `NAME` | yes |
| COL | `NAME.NNN` and `NAME` is taken (or claimed by a lower number) | suffix kept, report only | only when another rule changes the name |
| CASE | lower-case letters, ignoring the suffix and an `x[0-9]_` LOD prefix | upper case | yes |
| CHR | characters outside `A-Z a-z 0-9 _` | replaced with `_` | yes |
| DEF | Blender default base name (`Cube`, `Cylinder`, `Empty`, `Armature`, `Bone`, ...), any case, with or without suffix | none; typed inline | no |
| TKN | the proposed name is already used, or proposed twice | never applied | no |

- **Rename Selected** renames every ticked row in one undo step, then scans again. A target name that is taken at that moment is skipped and listed in the console, never forced. Linked library items are listed but locked. Bones in an armature that is in Edit Mode are skipped.
- **List:** filter by rule tags and by name; clicking a row selects the object (or the armature and its active bone); *Frame* zooms to the selection; *Tick All* and *Untick All* act on the rows the filter shows.

### Verified Behavior

- **Synthetic scene, headless Blender 5.2:** every rule produced the expected proposal; renaming applied 8 of 8 ticked rows and the rescan left only collisions, default names and the taken proposal.
- **Bone rename (assumption 1 confirmed):** renaming `wiper_l` to `WIPER_L` through `Bone.name` also renamed the vertex group and the F-Curve data paths `pose.bones["WIPER_L"]`. Object renames keep drivers, constraints, modifiers and NLA, which reference objects by pointer; names inside text blocks and Python expressions are not updated and not detected.
- **Production cockpit (scan only, nothing saved):** 1770 rows, 933 ticked by default; COL 1414, CASE 882, CHR 219, DEF 217, SFX 19. Only 19 suffixes can be stripped: the 623 suffixed names with a free base come in groups (`1 BODY BACKUP.001` to `.016`), so only the lowest number of each group takes the base and the others collide with it.
- **Blender 5.2 detail:** `PoseBone.select` exists, `Bone.select` does not; selecting a row uses the pose bone.
- **Not verified by a test:** the panel itself (list drawing, filters, inline editing, row selection); only the scan and rename functions were driven headless.

### Reasoning

- Project-free first slice: useful today, and the suffix check is the defect class with verified sim impact. The project cross-check slots in later as a classification fed by `names.classify` of the project-tree query API.
- Report, then apply only what is ticked: the tool cannot know references, so the artist decides.
- No platform constraints apply: Python in Blender, outside the C++ build.

### Scope & Expected Behavior

The name check runs on any `.blend` without the MSFS project. It never renames anything until *Rename Selected* is pressed, never forces a taken name, and can be undone in one step. Open: actions and materials (D5), the project cross-check, duplicate glTF node names across namespaces (a bone and an object, or two armatures, with the same name), and deployment to `tools/blender`.
