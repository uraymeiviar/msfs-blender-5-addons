## Session 1: Anisotropy in Material Preview and Rendered Views

- **Date:** 20261103
- **Developer:** uraymeiviar, Claude Opus 5.5

### Objective

In Material Preview and Rendered views, an MSFS Anisotropic material looked isotropic: Asobo's tree creates the anisotropic texture node and leaves it unconnected (a `TODO`). A hand-off from the glTF viewer work proposed a preview that uses the texture, without changing what is exported.

### Decisions (maintainer)

1. **Code in an FSS-owned module** (`anisotropic_preview.py`), called from marked lines in Asobo's files.
2. **Hair works fully**, not left out as the hand-off recommended: artists may add an anisotropic texture to Hair materials later.
3. **An "Update Material Nodes" operator**, not a new automatic update on opening a file. See the finding below: the add-on's existing rebuild on open already covers most cases.
4. **The File > Export loss is fixed for MSFS 2024:** see the design below.
5. **Soften the stripes** after looking in Blender: they were too strong under studio light. This accepts missing the hand-off's "EEVEE contrast above 0.05 with a sun".

### Design

- Each material keeps its Principled BSDF and its Material Output (target ALL) untouched. The preview adds a Principled with true anisotropy on an output with target CYCLES, and fanned isotropic lobes on an output with target EEVEE, because EEVEE ignores Principled anisotropy.
- Each engine prefers the output of its own target; the Khronos exporter follows the ALL output. The hand-off's design (only CYCLES and EEVEE outputs) lost the base color, normal and comp textures in File > Export with the target MSFS 2024.
- The preview nodes exist only while the material has an anisotropic texture, and are named `FSS Aniso ...`. An output must not be named `Shader Output Material`, which marks a legacy MSFS 2020 tree (`compat.has_msfs2020_node_tree`).
- `_update_normal_links` removes every link from the normal group, and the material's alpha link depends on the alpha mode. A mixin on `MSFS2024_Anisotropic` and `MSFS2024_Hair` relinks the branches after both.
- The artist's image is never changed. Asobo's `_validate_material_image`, modelled in the hand-off, swaps the property's image for a copy when the colour space differs; the differential test showed one more image in the glTF (27 to 28). A preview node with an image that is not Non-Color uses a private copy instead (`.fss_aniso_preview`).
- Node groups carry a version in their name: `.FSS Anisotropic EEVEE v2`, `.FSS Anisotropic Cycles v1`. A file saved with an older group moves to the new one at the next rebuild. Asobo's purge on open removes only its own groups, so a changed group needs a new name.

### Findings

- **The add-on rebuilds every material when a file opens** (`scene_loading.prepare_scenes`, `MSFS2024_SceneUtils.update_msfs2024_materials_graphs`), contrary to the hand-off. Existing materials get the preview by restarting Blender and opening the file. The rebuild is skipped when the separate `io_scene_gltf2_msfs` add-on is enabled; this is the case left for the operator.
- A Blender with an older add-on removes the preview at its own rebuild; exports do not change.
- EEVEE shows some straps hollow where Cycles shows them solid. This is the material's back-face culling, which EEVEE honours; it is the same without the preview. The hand-off's comparison used new materials without culling.
- After a deploy, opening a file builds the groups from the deployed copy, so a measurement with changed constants must remove them first. Six runs of the softness sweep measured nothing until this was done.

### Not Done, Noticed

- **Import of Anisotropic materials:** `AsoboAnisotropic.from_dict` has a misplaced bracket in `getattr` (`asobo_material_anisotropic.py`, `getattr(material, name == value)`), which looks like it would fail when a glTF with this extension is imported. Not run, not changed.
- **MSFS 2020 anisotropic texture:** an MSFS 2020 export reads `msfs_extra_slot1_texture`, not the MSFS 2024 property, so a material that has only the latter exports without the anisotropic extension. `Seat_Belt` and `RUDDER_BRUSH_STRIP` have that slot empty. The maintainer said this is not a problem for MSFS 2020 for now.
