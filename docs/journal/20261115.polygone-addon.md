# Polygone Add-on

[Journals](README.md) / **20261115.polygone-addon.md**
***

The Blender add-on that drives libPolygone (`H:/git-repos/libPolygone`): a UI only, as the library's concept decided
(libPolygone journal `doc/journals/20261112.libpolygone-concept.md`, decisions 2 and 4: an independent add-on that
loads the DLL with `ctypes` and passes flat arrays).

## Session 1: First Version (0.1.0)

### Request

The maintainer asked for one add-on panel named Polygone, with options to tune, that reduces the meshes of the
selected objects, to test the library in Blender.

### What Was Built

- `polygone/`: an add-on of its own (not part of `fss_blender_tools`), three modules:
  - `native.py`: the DLL's interface version 2 through `ctypes`, without `bpy`, so meshes reduce in worker threads
    (`ctypes` releases the GIL; the library reduces one mesh per call on one thread). The bundled DLL
    (`lib/windows-x64/polygone.dll`, libPolygone commit 1b60bcd, Release, imports only `KERNEL32.dll`) or one named in
    the add-on's preferences is loaded from a copy in the temporary folder, so a running Blender never locks a DLL
    that a libPolygone build writes, and Reload Library picks up a new build.
  - `mesh_io.py`: Blender mesh to arrays and back (below).
  - `ui.py`: settings on the scene (`fss_polygone`), the operator `polygone.reduce_selected`, the panel and
    subpanels (Attribute Weights, Feature Lines and Locks, Advanced, Last Run, Library), preferences.
- `tests/test_polygone.py`: background-Blender tests, synthetic scenes plus any `.glb` / `.gltf` named after `--`.
- `docs/user/polygone.md`: the artist guide page.

### Mesh Conversion

In, per mesh:

1. Triangles are Blender's loop triangles. Every face corner carries its normal (`corner_normals`), each UV map and
   each colour attribute (point colours expanded to corners).
2. Corners become one split vertex of the library when position, triangle group, UVs and colours are equal bit for
   bit and the normals differ by less than the Normal Merge Angle (default 1 degree). Keyed by position, not by
   Blender vertex, because the glTF importer keeps one Blender vertex per glTF vertex (SciFiHelmet: one per corner,
   70,074 vertices for 23,358 triangles), and corners equal in all but their Blender vertex would be seams the
   library cannot collapse. The angle is there because Blender stores custom normals with an encoding error: on
   SciFiHelmet, corners that had one normal in the glTF differ by up to about 1 degree after import (measured:
   70,074 split vertices with exact normals, 14,200 at 0.05 degrees, 14,085 at 1 degree, the glTF's own count).
3. The triangle group is material index × 2, plus 1 for a flat face of a mesh without custom normals. The library
   takes a vertex in one group only (`polygoneStatusUnsupported` otherwise, seen on BrainStem before the group was in
   the key). Corners of such flat faces take one normal per position (the area-weighted mean of the face normals
   there), so flat shading does not make every edge a normal seam (Fox: 576 to 540 triangles before, 576 to 58 after,
   as in the bench). With custom normals the corner normals are data and stay; a first version that also treated
   flat faces with custom normals this way made planar faces the importer had marked flat into group borders, and
   DamagedHelmet stopped at 2,630 triangles instead of 2,532.
4. Feature edges from sharp edges, marked seams and creases (each optional, with a weight) and from a feature angle
   between the two faces of an edge; edges without a face or between two vertices at one position are left out, as
   the interface requires. Locks from a vertex group (weight 0.5 or more), importance from another (1 + weight ×
   (strength − 1)), each per split vertex the largest over its corners.
5. Max Error is given in scene units and divided by the object's largest scale; the reported error is multiplied
   back.

Out: output vertices at one position are one Blender vertex. Each triangle is a face with its corners' UVs, colours
and custom normals; zero custom normals (Blender's own) on faces of a flat group, which get Flat shading. A face whose
three positions another face already uses (double-sided geometry the input had; CarConcept InteriorMid has 4) gets
its own vertex copies, since Blender holds no duplicate faces on one set of vertices. Vertex group weights come from
the input vertex each output vertex names as its source.

### Verified

Background Blender 5.2.2 (`C:/Program Files/Blender Foundation/Blender 5.2`), `tests/test_polygone.py` with all 23
Khronos samples of libPolygone's `samples/khronos`: 0 failures.

- Synthetic: ratio, triangle count and error-only targets; New Object and Replace Mesh (modifiers kept); modifiers
  applied; subset placement (every output vertex an input vertex); max error in scene units on a scaled object;
  materials, UVs, colours, unit normals and vertex groups on the result; all 69 locked vertices in place; flat,
  smooth and mixed shading kept; every result passes `Mesh.validate()` unchanged.
- Samples at 10 %: every mesh reduced, every result valid. Against the bench's unlocked run of the same library on the
  glTF files (`build/bench/unlocked/summary.md`): DamagedHelmet 2,532 triangles, error 0.20381 (bench 2,533,
  0.203811); SciFiHelmet 2,336, 0.14058 (2,335, 0.14058); GlamVelvetSofa 603 (603); MosquitoInAmber 6,539 (6,539);
  Fox 58 (58; its error differs, as Blender reduces the posed mesh).

Not verified: the panel drawn in an interactive Blender (all runs were in the background), and the add-on on
production `.blend` files.
