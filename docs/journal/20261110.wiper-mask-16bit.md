# Wiper Mask Generator: 16 Bits per Channel

[Journals](README.md) / **20261110.wiper-mask-16bit.md**

## Session 1: Float Bake, 16-Bit PNG

Date: 20261110. Base: eb05031.

### Trigger

The maintainer asked for the E2 wiper mask to follow the SDK texture guidance. The SDK page "Texturing Technical
Information" recommends a lossless format at 16 bits per channel (16 bpp PNG) as texture input, because MSFS remaps
the data before it compresses it. The Wiper Mask Generator created an 8-bit image and saved it as 8-bit PNG.

### What the Generator Did

- `set_v_colors` writes the sweep into a `FLOAT_COLOR` attribute of the projected wiper mesh: R = animation-in time,
  G = 1 - R, B = position along the blade, A = 1.
- `bake_texture` bakes those colors (DIFFUSE, color pass, selected to active) into the image made by
  `prepare_output_texture`, then saves it with `bpy.ops.image.save()`.
- The image was a byte image, so the float sweep was cut to 8 bits: about 250 distinct R (time) values over the
  whole sweep.

### Change

`wipermask_generator_msfs_2024/wipermaskgen_utils.py`, `prepare_output_texture`, marked `# FSS:`:

- `bpy.ops.image.new(..., float=True)`: the bake writes float values.
- `img.file_format = "PNG"`: the float image is saved as PNG; Blender writes a float image as PNG with 16 bits per
  channel.

Nothing else changes: the bake, the color space (Linear Rec.709, so the values are written unchanged), the file name
and the panel. The add-on is otherwise Asobo's; AGENTS.md now lists this change so that a new Asobo release keeps it.

### Runtime Behaviour Found

- Blender treats a float image's pixels as premultiplied and divides color by alpha when it saves a PNG. The baked
  mask has alpha 1 inside the sweep, 0 outside and a few partial-alpha texels at the edge, so the inside values are
  written unchanged. A float image filled through `Image.pixels` with color above alpha would be saved wrong; the
  generator does not do that.
- The generator needs a UI context (`bpy.context.area`); it cannot run in background mode. The verification used a
  Blender window started with a script that runs the bake operator through `context.temp_override` and quits without
  saving.

### Verification

Same file (E2 `COCKPIT.blend`), same two configurations (`WINDSHIELD_FL` and `WINDSHIELD_FR`, frames 0 to 100,
1024 px), once with the deployed unchanged generator and once with this repository's:

| | Unchanged (8-bit) | Changed (16-bit) |
| :--- | :--- | :--- |
| PNG sample type | uint8 | uint16 |
| Covered texels | 413586 | 413586 (no texel differs) |
| Distinct R (time) values in the sweep | 243 | 57824 |
| Largest difference on opaque texels, R / G / B | | 0.0106 / 0.0112 / 0.0066 |
| Mean difference on opaque texels | | 0.001 (8-bit rounding) |
| Largest alpha difference | | 0.002 |

The largest differences (up to 3/255) are the dithering Blender adds when it writes float values into a byte image.

Not run: an MSFS check of the 16-bit mask (the E2 cockpit uses it from this session on); no unit test, because the
generator needs a window.
