## Session 1: Viewport Bounds, Parent Highlight and Clickable Hierarchy

- **Date:** 20261011
- **Developer:** uraymeiviar
- **Agent:** Claude Code (Opus 5.5)
- **Branch:** dev/fs24/uray
- **Base Commit SHA:** 0e7e3a48494f1b912516791debfedeb3e28c1316 (2026-10-10 11:38:30 +0700)

### Problem Statement

The cockpit `.blend` groups its parts under empties (`EMPTY_COCKPIT_ROOT`, `EMPTY_PEDESTAL`, `EMPTY_AUDIO_L`, ...) that set the parts' parent and origin. An empty shows only its origin, so the artist cannot see which parts it holds, and with about 1000 empties and 3600 objects it is hard to tell where a selected part sits in the hierarchy.

The maintainer asked for the empty's *Display As* to show the box around its children without adding a box object to the scene, then for the parents of a selected object to be highlighted, then for a list of those parents in the viewport that can be clicked to select one.

### Maintainer Decisions

- **No scene data:** nothing is added to the scene, the Outliner or an export. Blender's *Display As* list cannot be extended by an add-on, so the feature is a viewport overlay.
- **Box extent:** computed from the direct children's boxes, so an empty's box covers all its descendants; hidden descendants count.
- **Global switch only:** a per-empty toggle was built first and then removed; the overlay is controlled only from the *FSS Tools* sidebar.
- **Parents of a selected object:** the direct parent (if it is an empty) is drawn as a solid light-magenta box with its origin crosshair; the empties further up to the root as dashed light-magenta boxes without crosshair. While any non-empty object is selected, the other empties' boxes are hidden.
- **Clickable boxes:** not done (considered and skipped). The hierarchy text is clickable instead.

### Solution Intent & Approach

Module `empty_bounds.py` of the `fss_blender_tools` add-on; panel *Empty Bounds* in the 3D View sidebar tab *FSS Tools* with *All / Selected / Off*, *In Front* (draw over the geometry) and *Hierarchy Text*.

- **Boxes:** a `POST_VIEW` draw handler. Each object's box is kept in its own local space and built bottom-up: its own evaluated `bound_box` (for geometry types) united with each child's box transformed into its space. A box follows the empty's rotation. Boxes are cached per object; a depsgraph update drops the cache of the updated object and its ancestors (current and previous parent chain, so reparenting is handled); collection changes, frame changes, file load, undo and redo drop the whole cache.
- **Objects that are not evaluated:** an object disabled in viewports (monitor icon) has a stale `matrix_world`. For a child or parent that is not visible, the parent-relative transform (`matrix_parent_inverse @ matrix_basis`) is used instead; it is exact for object parenting without constraints and ignores constraints on such hidden objects.
- **Styles:** other empties faint blue 1.5 px, selected and active empties in the theme colours 2 px, direct parent solid light magenta 1 px, empties further up dashed light magenta 1 px (dashes of about 6 px on screen). Each drawn empty except the dashed ones gets its origin as a crosshair with the shape and size of Plain Axes. *All* draws every empty unless a non-empty object is selected; *Selected* draws the selected empties and the parents of the selection.
- **Hierarchy text:** a `POST_PIXEL` handler lists the active object's parent chain, root first and indented, in the bottom-right corner (left of the sidebar when it overlaps the viewport), with `+N more selected` when more is selected. Colours follow the boxes; non-empty parents are grey.
- **Clicking the text:** a persistent 2D gizmo group with one gizmo per row; each gizmo hit-tests the row rectangle that the text drawing uses and runs `fss.hierarchy_select` (click: select only that object and make it active; Shift+click: add or remove). Gizmos get the click before the active tool, so a click on a name does not also select the mesh behind it, and clicks elsewhere behave normally. Rows highlight on hover.

### Verified Behavior

- **Box maths, headless Blender 5.2:** a rotated parent empty, a nested empty, a child disabled in viewports, moving a child, reparenting and deleting all gave the expected boxes; the disabled child was placed wrong until the parent-relative fallback was added.
- **Production cockpit:** 994 empties, 934 with a box. A full cache rebuild takes about 29 ms, the cached pass 0.4 ms, and the pass after moving one object 0.9 ms.
- **Real viewport (portable Blender window, screenshots):** *All* and *Selected* draw without errors. With `AUTOTHROTTLE_DC_LEFT` selected, its chain (`EMPTY_PUSH_AUTOTHROTTLE_LEFT` up to `EMPTY_COCKPIT_ROOT`, through `ARMATURE_THROTTLE_L`) is drawn as specified, the armature skipped. With `B_GS_AFCS_SPEEDM_SELECT_KNOB` selected, `EMPTY_GSHIELD_FGP_SPEED` is solid with crosshair and `EMPTY_GLARESHIELD`, `EMPTY_MAINPANEL`, `EMPTY_COCKPIT_ROOT` are dashed, and no blue boxes are drawn.
- **Click, with simulated mouse events (`--enable-event-simulate`):** hovering the `EMPTY_GLARESHIELD` row highlights it; clicking it left `EMPTY_GLARESHIELD` as the only selected and active object; a click elsewhere in the viewport still selected normally.
- **Maintainer:** tested the boxes and the parent highlight in the installed Blender 5.2 during the session.

### Limitations

- The overlay follows the viewport *Overlays* switch; clicking the text also needs the *Gizmos* switch and works only in Object Mode.
- Hovering a row shows Blender's gizmo tooltip, which covers the rows below for a moment.
- With *All* and only empties selected, the pedestal alone draws hundreds of boxes.

### Affected Files / Key Changes

- `msfs-blender-5-addons` repository: `fss_blender_tools/empty_bounds.py`, `fss_blender_tools/__init__.py`, `README.md`.
- `codes/wasm/doc/journal/20261011.fss-blender-tools-empty-bounds.md` (this journal).

### Reasoning

- A draw handler, not helper objects: the boxes must never reach the Outliner, a save as geometry or an export.
- Bottom-up cached boxes keep redraws cheap on a 3600-object cockpit; only changed chains are recomputed.
- Gizmos rather than a keymap hook for clicking: they take priority over the active tool only where they are hit, and give hover feedback.
- No platform constraints apply: Python in Blender, outside the C++ build.

### Scope & Expected Behavior

Viewport-only aid; the `.blend` keeps only the three scene settings. Not deployed to `tools/blender` yet.
